# 放进项目 AGENTS.md 的一段

两种情况用：Agent 不支持技能；或者想让这个项目里每次改功能都强制先看树，不依赖技能是否被自动触发。

复制下面一段到项目根目录的 `AGENTS.md`。Claude Code 读 `CLAUDE.md`，在 `CLAUDE.md` 里加一行 `@AGENTS.md` 即可引用同一份。

```markdown
## 产品树

产品树在 `docs/product-tree.md`，用它管整个产品的设计：树顶写产品描述和使用者，下面分核心功能、扩展功能、界面与交互三枝。功能节点写效果、唯一数据源、核心实现、界面组件和全部入口，前端和后端写在同一个节点里，页面和接口都是入口。界面与交互记页面、页面布局、任务流程、交互模式、用词、设计变量和组件库。设计稿和规格文件挂在树上对应的行下，不抄进树。

新增、修改、删除功能、页面或流程，新增或改布局、表单、列表列、操作方式、设计稿，或给已有功能加入口之前：

1. 把需求写成效果（去掉入口后剩下的那句话），在树里和代码里找改同一份数据、结果相同的功能。
2. 效果相同只是入口新：加到已有节点的入口下，新入口调用该节点的核心实现，不另写一套。
3. 已有两套做法做同一件事：先合并成一套，再做需求。合并会改变用户看得到的行为时，只把不同点列给人选。
4. 全新效果才新增节点。产品缺它不成立是核心功能，否则是扩展功能并写明依赖。
5. 同一份数据在多个页面显示或编辑，用节点「界面」里登记的同一处定义。
6. 新页面先查页面表：已有页面回答同一个问题，就加到那一页。新页面用页面布局里登记的布局，操作做法照交互模式，界面名词照用词表，颜色、间距、字号用设计变量。
7. 改变用户完成某件事的步骤，先改任务流程那一条。同一件事多一个起点，加在已有流程里，不另起一条。
8. 先改树，再改代码，同一次提交。设计稿、规格文件改了，挂它的那一行跟着改。入口里不写业务规则。
9. 本机装了产品树技能时，改完树用技能目录里的 `render.py <树文件> --check` 检查编号；要看图用 `render.py <树文件> -o <忽略的目录>/product-tree.html` 生成一张可展开的思维导图（功能 → 子功能 → 入口和重复做法）。节点只写短名称，长句仍看树文件，不手画。
```
